Why sand3d

Fewer tokens for the same object

The token figure, part by part. Every program is counted the same way: o200k_base tokens, code only (docstrings and comments are not counted). A ratio is the other program's tokens over sand3d's.

Who wrote what:

  • sand3d: the programs of this repo, written for it; each matches its reference mesh (the CAD model's, or the articulated object's), the CAD parts at an F-score of 0.95 at 2 % of the diagonal.
  • Blender Python: written by an LLM from the CAD part's source; right part means it runs and its mesh matches the CAD model's.
  • CadQuery, FeatureScript: the program the CAD dataset ships for the part. Zero-To-CAD-1m (Apache-2.0) is synthetic CadQuery; CADFS (CC BY 4.0) holds real Onshape designs in FeatureScript.
  • Articraft: the program Articraft-10K (CC BY 4.0) ships for the object, written with its own Python SDK (meshes, joints, materials, masses), its tests left out; five also build shapes with CadQuery.

Not compared: objects that come as meshes (Objaverse-type assets): no program exists to set beside sand3d's; the articulated objects in Blender Python: none was written; the CADFS parts in CadQuery: their source is FeatureScript.
